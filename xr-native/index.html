🥽 Halloumi-Quest · native Vulkan + OpenXR

Phase 1.4 · v0.1.3-dev

Native Android APK for Meta Quest 2 that renders 2DGS + SV Gaussian scenes in immersive VR — same asset format as the flat viewer (.bitymi bundles), rendered directly against Vulkan + OpenXR without the browser.

Distributed sideloaded from this site. No Meta Store, no App Lab, no Meta review. Meta doesn't see the app, doesn't gate it, doesn't take a cut.

Why native (and not WebXR)?

WebXR + WebGPU was the first attempt: same code as the flat viewer, plus a stereo render loop. It compiled and submitted command buffers on Quest 2, but the Adreno 650 WebGPU driver crashes the GPU context during execution — for any combination of compute passes, and even for a minimal cleared-only render pass. A minimal WebGPU triangle works, but Halloumi's resource graph does not. That's the browser/driver floor as it stands in 2026 on Quest 2 hardware. See the WebXR fork (Halloumi-XR) for the diagnostic history.

Native Vulkan + OpenXR bypasses all of that: direct GPU access, mature drivers, and it opens the door to Quest-specific features (foveated rendering, controller tracking, spatial anchors).

🧭 Diagnostic result: the reference quest-xr-reference.apk opens instantly on Quest 2 — the device + Meta runtime + loader are all fine. Halloumi-Quest v0.1.3-dev (below) still hangs on the loading dots. So the bug is in Halloumi's code, upstream of any rendering. Rather than more speculative patches on our tree, we forked Quest-XR entirely as the new base — same OpenXR+Vulkan bring-up path that already boots on your headset. The splat renderer will splice into that fork, not the other way around.

Phase 1.3 build. Renders the tiny brain (15k Gauss, bundled as an APK asset) in immersive VR — full 2DGS pipeline with Spherical Voronoi colour, per-eye projection, CPU 16-bit radix sort, Vulkan graphics pipeline with premultiplied-alpha blending. The whole per-Gauss compute (cov3D, view Jacobian → cov2D, SV softmax) runs on the CPU in native C++ and hands off to a thin Vulkan graphics pipeline. Scene appears ~2.5 m in front at eye height.

Debug menu built-in. The app boots into a blue "menu" state and either advances to splats after 10 s or on a controller-trigger press. If either eye shows red, init failed — grab a logcat and check the halloumi-quest / halloumi-scene / halloumi-render tags to see which step aborted. If it hangs on Meta's loading dots after ~30 s, that's before our code runs at all (unlikely as of v0.1.2-dev after the OpenXR 1.0 apiVersion fix).

Version check: after install, App Info screen should read versionName 0.1.2-dev. If it says an older version, delete first — Meta caches installs by package name.

How to install (one-time setup)

You only need to do this once per headset. After that, every future APK from this site installs with a single tap.

Step 1 · Enable Developer Mode on your Quest

  1. Create a free Meta developer organisation at developer.oculus.com — just pick any name, no company info or ID verification required.
  2. Open the Meta Quest phone app on your phone.
  3. Devices → [your Quest 2] → Developer Mode → toggle on.
  4. Reboot the headset once.

Step 2 · Install via SideQuest from your PC

Meta locked down browser-based APK installs on recent OS builds — the Quest browser can download an APK but the built-in file manager refuses to hand it to the installer with an "unsupported file type" error. So we install from a PC:

  1. On your PC, install SideQuest.
  2. Plug the Quest into your PC via a USB-C data cable (charge-only cables won't work — SideQuest shows "device not connected").
  3. Put the Quest on and approve the "Allow USB debugging" prompt when it appears. Check "Always allow from this computer".
  4. In SideQuest, top-right toolbar → the "Install APK file from folder on your computer" icon (box with down-arrow) → pick the APK you downloaded above.
  5. In the Quest, App library → filter dropdown (top-right) → Unknown Sources → launch Halloumi-Quest.

ADB variant (if you already have platform-tools): adb install halloumi-quest-phase1-dev.apk.

What's under the hood as of v0.1.2-dev

  • OpenXR 1.0 session against Meta's Quest 2 runtime; XR_KHR_vulkan_enable2 for the Vulkan binding; local-floor reference space with local fallback; one immersive-vr projection layer with two eye views.
  • Vulkan 1.1 graphics pipeline — single-attachment colour render pass (format enumerated at runtime, SRGB preferred), static-quad vertex binding + per-instance (ndc.xy, conic.xyz, rgba, extent_px) binding, premultiplied-alpha blend, dynamic viewport/scissor, vec2 viewport_px push constant. Framebuffers cached per XR swapchain VkImage.
  • CPU splat pipeline in native C++: SV-aware binary PLY parser (ports the JS loader), per-frame per-eye projection (cov3D → cov2D via perspective Jacobian → conic + extent), SV eval (softmax over −τ·|site−dir| chord distance), frustum-culled + 16-bit radix sort back-to-front. Persistently-mapped host-visible instance buffer for zero-copy per-frame upload.
  • Debug state machine — Menu (blue) / Splats / Error (red); trigger click or 10 s timeout advances. Any XR/Vulkan failure is logged at ERROR level via the halloumi-quest logcat tag (no more silent aborts).
